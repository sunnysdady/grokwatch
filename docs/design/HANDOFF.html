项目目标与定位

GrokWatch 是一块大屏骑行伴侣手表，补 Apple Watch 在骑行场景的空白。只做三件核心事：导航（Android App io.grokwatch.app 读取高德/Google 地图的导航通知并转发）、码表、Grok 对话；另有语音待办。

  • 通知功能已删除：顶部下拉面板整块删掉，下滑手势不绑定任何功能；App 0.7.0 只保留导航通知读取。
  • 控制中心：从底部上滑呼出。
  • 硬件：M5Stack StopWatch，ESP32-S3，466×466 圆形 AMOLED，QSPI 40MHz（整屏重绘约 22ms，上限约 46fps；局部动画可接近 60fps；不超频到 80MHz）。
  • 软件：LVGL，ESP-IDF v6.1.0，基于 xiaozhi-esp32（上游 39d23ae）。
  • 按键：蓝键 按住说话；黄键 单击下一页 / 双击回首页 / 长按音量；电源键 单击亮灭屏 / 双击菜单 / 长按关机。

Sunny 的设计理念

以下是 Sunny 本人反复强调的要求，优先级高于任何"好看的想法"。

  • 体验和交互第一（乔布斯式），不要花里胡哨。空间不够就砍功能，不牺牲体验；通知是第一个被砍的。
  • 风格 = Apple HomeView，推翻旧的 Apple Watch Ultra 风格。柔和圆角卡片，大号圆体数字 + 小标签，低饱和青绿/薄荷，一张表盘一个色相。
  • 不用毛玻璃、不用大背景图：阳光下可读性和帧率优先。
  • 夜间 = 压暗的暖白，绝不用红色。按日出日落自动切换：App 根据位置算出日出日落发给手表，离线沿用上次的值，1–2 分钟渐变；控制中心手动开关优先，直到下一次日出/日落。不跟随手机深色模式（很多人手机常年深色，白天骑行会看不清）。
  • 待机 = 类 iPhone StandBy：两行上下叠放的矢量绘制圆角数字，26px 笔画，薄荷色 #E8EFC4（苹果字体无法授权开源，所以自己画）。
  • 动画保留（交互加分项）：目标 60fps，底线 30fps，达不到就直接切换不做动画。
  • 输入响应 <100ms；堆内存空闲 ≥20%。
  • 从一开始就为 Wi‑Fi OTA 和 App 内升级设计。
  • 可开源：代码里不能有密钥、个人信息、内网地址。
  • 守住底线：Sunny 自己说过会有天马行空的建议，要守住最终目标，有分歧直接说。

HomeView 研究

完整报告见 docs/HomeView-REPORT.md，迭代自审见 docs/CRITIQUE.md。结论：HomeView 好看靠的是克制的规则，不是玻璃特效。

  • 一张表盘一个颜色：所有元素是同一色相的明暗（紫 #3636A5→#8B8BF5，绿 #134B49→#649C96），卡片明度差约 10–15%。
  • 一个超大数字当主角，辅助文字小而淡（同色 50–60% 透明度）。大数字用 Regular/Medium，小标签用 Semibold。
  • 圆角统一、层级靠明度，不用描边和阴影；内外圆角同心。
  • 表盘随时间变化，夜间靠压亮度（最低 0.3 nit）而不是换红色。
  • 留白 >60%；一屏最多 3 种字号。
  • 玻璃折射只是点缀，去掉后骨架仍成立 → 手表上用纯色扁平卡片。

字体与字号

  • 主数字：Nunito Medium 280px（码表速度，约屏高 40%）/ 150px（导航距离等）。OFL 授权，与矢量待机数字同一圆体语言。
  • 辅助行：26px（同字族拉丁字母，例 18.6 km 0:52）。
  • 中文：街道名等 20px（v3 原型用了 24px，但 24px 中文要 +95KB，固件定为 20px）。
  • 字号成本：Nunito 子集压缩约 50KB。

版面与形状

  • 圆角：卡片 28，瓷砖 36，胶囊 = 全圆（高度/2）。
  • 每页一个主角 + 一行辅助，去掉顶部时间、底部提示、多卡片。
  • 圆屏安全区：内容半径 ≤215（速度环 r216，瓷砖角距圆心 ≤221）。
  • 纯色底，不用渐变（RGB565 会色带，也省渲染）。
  • 三位数自动缩到 70%；距离 ≥1000m 切 km（1.2 km），否则 m；单位小字贴在数字右下。
  • 码表不写 km/h；心率先从主屏拿掉。
  • 控制中心：四个大图标块，开亮一级、关暗一级。

动效

  • 左右翻页：横向滑入（140px 位移 / 240ms，从手指方向进入，ease-out 收尾）；帧率连续两次 <30fps 就改直接切换。
  • 通用：页面切换约 280ms，cubic-bezier(0.32,0.72,0,1)；按下缩放 0.96 / 100ms。

空间预算

OTA 槽 ota_0/ota_1 各 0x3f0000 = 4,128,768 B。当前约 80%，目标 ≤75%。每加一个字号/字体都要先算账。

已知问题

  • 真机启动后重启：2.6.2、2.6.3 OTA 后约 20–30 秒内重启，回滚到 RC6（2.5.3），服务器又重新下发，形成 OTA 循环（OTA 目录已清空停止）。根因未知，怀疑压缩字体 + 堆压力、或看门狗。2.6.4 加了 NVS 启动记录来抓重启原因。
  • Sunny 反馈整体卡顿（可能与循环升级有关，未确认）。
  • Grok 容易被误触触发（2.6.4 改为仅中心刻意长按，未上真机验证）。
  • 手表当前运行 RC6（2.5.3）。
  • OTA 回滚只在主机逻辑测试过，真机未验证；QEMU 不支持八线 PSRAM。
  • 固件占槽约 80%，需瘦身到 ≤75%。

给 Codex 的硬规则

  • 不经 Sunny 同意，不刷机、不推 OTA（不往 data/bin 放 bin）、不推 GitHub、不发布。
  • 永不提交 Wi‑Fi 凭证、内网 IP（sdkconfig.private 已 git-ignore）、keystore、token。
  • 任何真机推送之前，先给 Sunny 看模拟器效果图。
  • 先写测试再修；每项标注四种状态之一。
  • 每个版本报告真实的 fps、内存、OTA 槽占用，不编数字。
  • 汇报结构：修复与根因 / 测试用例与结果 / 真机验证 / 未解决 / 提交号与产物。
  • 自审发现的问题先改完再给 Sunny 看。
