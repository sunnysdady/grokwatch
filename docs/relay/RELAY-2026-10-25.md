# GrokWatch 接力文档（2026-10-25 00:10 北京时间）

## 当前状态（先看）
- 手表（M5Stack StopWatch, ESP32-S3, 466 圆屏 AMOLED）**卡住**。最后一次"刷回 RC6"（整片镜像写 0x0）在中途被中止，flash 可能是半写状态。
- 手表通过 USB 连在 MacBook Air，端口 `/dev/cu.usbmodem101`，esptool v5.6.0。

## 要解决的三个问题
### 1. 滑动/动画帧率低（核心）
- 实测 RC6 / 2.6.x：页面动画 9–25fps（日志 `NavUI: fps=17..25`），目标 60fps，底线 30fps。
- 屏：QSPI 40MHz，全屏一帧约 22ms 传输 → 全屏重绘理论上限约 45fps。
- 待查：渲染耗时 vs 刷屏等待；LVGL 部分刷新/双缓冲/DMA；字体（曾改为不压缩）；是否每帧全屏重绘。
- 内存：内部 SRAM 空闲约 65KB，最低约 33KB。
- 已加了逐帧剖析命令 `prof N` / `proffull N`（USB 测试控制台，仅私有构建 `GW_TEST_CONSOLE=1`），但还没拿到真机数据。

### 2. 测试版反复重启（已找到原因，修复未验证）
- `gw-prof.bin`：`prof()` 里 `TaskStatus_t a[40], b[40]` 放在 4KB 的 gw_console 任务栈上 → `stack overflow in task gw_console`，加上中断看门狗超时，连崩 9 次。
- 修复（`gw-prof-fix1.bin`，未提交）：改用 static 数组；任务栈改为 6144 字节；强制重绘定时器周期从 0 改为 33ms。
- 我的测试守护脚本把正常开机打印的 `rst:0x15 (USB_UART_CHIP_RESET)` 误判为崩溃，触发了自动刷回，导致现在的混乱。macOS 打开串口时，DTR/RTS 线变化会让芯片复位，需要不拉控制线（或用 `--after no-reset`）。崩溃判据应只看 Guru Meditation、stack overflow、abort 和 rst:0x4/0xc。

### 3. OTA 升级循环（根因未明）
- 2.6.x 经 OTA 升级后在 30 秒内重启 → bootloader 回滚到 2.5.3 → 服务器又发新版 → 循环。gw_health 要运行满 30 秒才把镜像标记为 valid。
- 2.6.4 新增开机记录（NVS bootrec：boots、crash_boots、复位原因），但还没在 OTA 场景下拿到数据。服务器 OTA 目录已清空，在此之前不要往里放固件。
- 疑点：关闭唤醒词时的监听/音频任务、字体或堆内存压力、看门狗。
