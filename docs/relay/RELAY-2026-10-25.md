# GrokWatch 固件接力文档（Codex 接手版）

更新：2026-10-25 北京时间（UTC+8）。本分支 `handoff/homeview-design` 已包含**当前**固件代码，不需要访问我们的机器。

> 状态词只用四种：已写代码 / 已过自动测试 / 已过模拟器 / 已过真机。

## 0. 一句话现状
- 手表现在跑 **RC6**（2.5.x 系出厂镜像），**已过真机**：刷回后连续观察 150 秒，没有重启。
- **2.6.4**（带待机时钟）开机约 1–2 分钟后崩溃，崩在 LVGL 取字形宽度（见 P0）。在修好之前不要刷任何 2.6.x，也不要往 OTA 目录里放固件。

## 1. 项目目标与优先级
- 产品：骑行副表。三件事：导航（转向箭头、距离、路名）、码表（速度）、Grok 语音对话。
- 优先级：**稳定 > 帧率 > 外观**。
- 帧率：目标 60fps，底线 30fps。
- 外观：HomeView 风格新主题（一种主色、一个主角元素加一行副信息、平面色块，夜间为调暗的暖白而不是红色），**尚未写进固件**，设计在 `docs/design/`（HANDOFF.html、mockups）。修 bug 不要顺手改主题。

## 2. 硬件
- M5Stack StopWatch：ESP32-S3、16MB flash、八线 PSRAM（80MHz）。
- 466×466 圆形 AMOLED，QSPI 40MHz，全屏一帧传输约 22ms，因此全屏重绘理论上限约 45fps。
- 内部 SRAM 空闲约 65KB，最低约 33KB（RC6 实测）。

## 4. 构建
1. 上游：`git clone https://github.com/78/xiaozhi-esp32 && git checkout 39d23ae`（完整哈希见 `firmware-patch/UPSTREAM_BASE.txt`）。
2. `git apply firmware-patch/upstream-outside-board.patch`
3. 把 `firmware/board/` 整个复制到 `main/boards/m5stack/stopwatch/`。
4. ESP-IDF **v6.1.0**（commit `9a97f6c54ec638111ce55cd36581b3c192f15207`），组件版本由 `dependencies.lock` 固定。
5. 公开构建：
   ```
   . $IDF_PATH/export.sh
   idf.py -B build -D SDKCONFIG=sdkconfig.ble build
   ```
   产物 `build/xiaozhi.bin`（app），版本号在 CMakeLists 的 PROJECT_VER。
6. 私有测试构建（带 USB 控制台）：`idf.py -B build_priv -D SDKCONFIG=sdkconfig.private -D GW_TEST_CONSOLE=1 build`。
7. 凭证注入：Wi‑Fi 写在 git 忽略的 `secrets_gen.h`（模板 `secrets_gen.h.example`，宏 `WIFI_HOME_SSID/PASS`、`WIFI_HOT_SSID/PASS`）；没有该文件时宏为空，照样能编。自己的 OTA 地址写在 git 忽略的 `sdkconfig.private`（从 sdkconfig.ble 复制后改 `CONFIG_OTA_URL`）。**带凭证的 bin 绝不能公开。**
8. 分区：`partitions/v2/16m.csv`（ota_0 在 0x20000）。

## 5. 刷机（只有 Sunny 同意后才能做，见第 10 节）
- 刷 app：`esptool erase-region 0xd000 0x2000`（清 otadata，回到 ota_0）然后 `esptool write-flash 0x20000 xiaozhi.bin`。
- 恢复 RC6：整片出厂镜像写 `0x0`（约 11MB，约 40 秒；会清 NVS，Wi‑Fi 可能要重配）。镜像不在仓库里，由 Sunny 那边保管。
- 进下载模式：按住 BOOT 再插 USB。

## 6. USB 测试控制台（私有构建）
命令：`swipe l|r|u|d`、`tap`、`longpress`、`page n`、`stat`、`fps on|off`、`touchlog on|off`、`prof N`、`proffull N`。
帧率日志形如 `NavUI: fps=17`。

## 7. 串口陷阱和崩溃判据
- macOS 打开串口时 DTR/RTS 变化会让芯片复位，日志出现 `rst:0x15 (USB_UART_CHIP_RESET)`。**这是正常开机，不是崩溃。** 用 pyserial 打开时先 `s=serial.Serial(); s.dtr=False; s.rts=False; s.port=...; s.open()`；esptool 用 `--after no-reset`。
- 崩溃判据只认：`Guru Meditation`、`stack overflow`、`abort()`、`rst:0x4`、`rst:0xc`、看门狗 `Task watchdog` / `Interrupt wdt`。
- 自动化脚本：出现一次真崩溃就停止发送命令，不要自动重刷；自动重刷曾把手表刷成半写状态。

## 8. 当前 bug（按优先级）

### P0：2.6.4 开机 1–2 分钟后崩溃（很可能也是 OTA 循环的根因）
证据（真机串口，2.6.4 私有构建，以及带 prof 的测试版）：
```
Guru Meditation Error: Core 1 panic'ed (InstrFetchProhibited)
PC=0xfffffffd
lv_display_refr_timer -> lv_obj_update_layout -> lv_label_event -> lv_font_get_glyph_width
```
PC=0xfffffffd 说明调用了一个已失效的函数指针，最可能是某个 `lv_font_t` 已被释放或被覆盖，标签布局时调用它的 `get_glyph_dsc`。

已确认的代码事实：
1. `gw_ultra.c:9-12`：页面字体 `F20/F21` 是 `gz_20` 的**拷贝** `f20_rt/f21_rt`，它们的 `.fallback` 由 `gw_faces_set_fallback()` 设置。
2. `nav_ui.cc:104`：`gw_faces_set_fallback(lv_obj_get_style_text_font(scr, LV_PART_MAIN))`。这里存的是**当时**主题文字字体的裸指针。
3. 上游 `main/display/lvgl_display/lvgl_display.cc` 的 `SetTextFont()` 会换掉主题字体并释放旧字体（`previous_*_font.reset()`），只重绑 LVGL 样式，**不会**更新我们的 `f20_rt.fallback`。`assets.cc:301` 在资源分区加载后调用它。
4. 同一文件 `AddTextGlyphs()`：服务器推送字形时，会给主题文字字体挂 `DynamicGlyphCache` 的 fallback 并 `Rebuild()`。
5. 2.6.2（`ba3b99b`）起，内置文字字体从 `font_noto_sans_basic_30_4` 改成 `20_4`（`main/CMakeLists.txt`），`TEXT_FONT_SIZE` 随之变为 20，影响资源字体和推送字形。RC6/2.5.3 用 30_4，没有崩溃。
6. 2.6.x 其他字体相关改动：`3da3d28` 压缩 gu_* 并删掉 Sunghyun 字体、加矢量待机数字（`gw_ultra.c:308` 起，不用字体）；`6549020` 又把 gu_* 改回不压缩；`07dceca` 删掉 gz_21b（F21 改为 gz_20）。

推断（未验证）：
- **头号嫌疑**：`f20_rt/f21_rt.fallback` 悬空。资源加载（联网后约 1–2 分钟）或字形推送替换/释放了主题字体，中文标签（F20/F21，比如待机或 Grok 页）找不到字形时走 fallback，调用已释放的字体。
- 次嫌疑：gu_* 压缩/不压缩切换后 `cache` 或 `dsc` 不一致；在 LVGL 锁外改标签文字（检查 nav_ui.cc 和 gw_grok.c 中从网络/音频任务调用 `lv_label_set_text` 的地方）。

建议的修法方向：fallback 不要存裸指针。可以每次取主题当前字体，或者给 SetTextFont 加回调，在换字体时重设 `f20_rt.fallback`；也可以干脆让 fallback 指向静态内置字体 `BUILTIN_TEXT_FONT`。修完用 `CONFIG_LV_USE_ASSERT_*` 加 sim 复现，再请 Sunny 同意上真机。

### P1：帧率 9–25fps
- 真机：2.6.x 滑动 9–13fps；RC6 17–25fps。
- 已做：`lcd_display.cc` 改双缓冲，每块 466×16 行；2.6.4 的调速器连续两次低于 30fps 时改成直接切页（只过了自动测试）。
- 待查：渲染时间和 QSPI 等待各占多少（`prof`）；每帧是否全屏重绘；PSRAM 缓冲 + DMA；降低动画区域；字体解压开销。

### P2：OTA 循环防护
- 现象：2.6.x 经 OTA 升级后 30 秒内重启 → bootloader 回滚到 2.5.3 → 服务器又下发 → 循环。
- `gw_health` 要运行满 30 秒才把镜像标为 valid（`application.cc` 中的上游 `MarkCurrentVersionValid` 已对本板关闭）。
- 2.6.4 有 NVS 开机记录（boots、crash_boots、复位原因），放在 OTA 请求体 `board.gw_boot` 里。
- 需要：服务器端同一设备、同一版本连续失败 N 次后停止下发；固件端回滚后上报被拒的版本号。

### 已修，未上真机
